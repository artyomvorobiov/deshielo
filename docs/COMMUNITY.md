# Сообщество: сервер, запуск и модерация

В приложении есть вкладка **«Сообщество»**. Пользователи публикуют свои рецепты с фото, ищут чужие и оценивают их, а под любым рецептом — и своим, и из каталога — показывают, «как получилось», с фото и звёздами.

Для этого нужен небольшой сервер. Используется [PocketBase](https://pocketbase.io): один исполняемый файл, внутри база SQLite, аккаунты, хранилище фото и REST API. Всё серверное лежит в папке `server/`:

```
server/
  pb_migrations/   схема базы и права доступа — применяется сама при запуске
  pb_hooks/        логика на сервере: фильтр грубых слов, рейтинги, автоскрытие по жалобам
  tests/           тесты API (run.sh), демо-данные (seed.py)
```

Пока сервер не указан в настройках сборки, вкладки «Сообщество» в приложении нет — остаётся полноценная книга рецептов без регистрации.

## Как это устроено

| Коллекция | Что хранит | Кто что может |
|---|---|---|
| `users` | почта, пароль, имя, согласие с правилами | имя видно всем, почта — только владельцу; удалить аккаунт может только сам пользователь |
| `recipes` | рецепт: название, описание, категория, кухня, время, порции, ингредиенты, шаги, до 6 фото, черновик или опубликован | читают все (черновики — только автор), правит и удаляет только автор |
| `reviews` | оценка 1–5, текст, фото результата; ссылка на рецепт сообщества **или** id рецепта из каталога | один отзыв от человека на рецепт; свой рецепт оценить нельзя |
| `catalog_ratings` | средние оценки рецептов каталога | пишет только сервер |
| `reports` | жалобы на рецепты и отзывы | видит только администратор |

Что делает сервер сам:
- **рейтинг** пересчитывается после каждого нового, изменённого или удалённого отзыва. Для сортировки «Лучшие» используется байесовская оценка: один отзыв на пять звёзд не обгонит сотню четвёрок с плюсом;
- **поиск** работает без учёта регистра и буквы «ё» (у SQLite с кириллицей это само не получается — сервер хранит поисковый текст в нижнем регистре);
- **фильтр грубых слов** не пропускает мат в названиях, рецептах, отзывах и именах;
- **автоскрытие**: рецепт или отзыв, на который пожаловались три разных человека, сразу скрывается до решения модератора;
- **ограничение частоты запросов** от перебора паролей и спама;
- при **удалении аккаунта** удаляются все его рецепты, отзывы и фото, рейтинги пересчитываются.

Приложение хранит токен входа в Keychain, а фото перед отправкой уменьшает до 1600 пикселей и перекодирует. Метаданные фото, в том числе геопозиция, на сервер не попадают.

## Попробовать на своём Mac за 5 минут

1. Скачайте PocketBase для macOS (Apple Silicon — `darwin_arm64`, Intel — `darwin_amd64`) со страницы [релизов](https://github.com/pocketbase/pocketbase/releases). Проект проверен на версии **0.40.5**: её же использует CI.
2. Распакуйте файл `pocketbase` в папку проекта и запустите сервер:
   ```bash
   ./pocketbase serve --migrationsDir server/pb_migrations --hooksDir server/pb_hooks
   ```
   macOS может не дать запустить файл из интернета. Тогда один раз выполните `xattr -d com.apple.quarantine pocketbase`.
3. В другом окне Терминала создайте администратора и заполните ленту демо-рецептами:
   ```bash
   ./pocketbase superuser upsert admin@example.com очень-длинный-пароль
   python3 server/tests/seed.py
   ```
   Панель администратора откроется по адресу http://127.0.0.1:8090/_/. У демо-аккаунтов `anna@example.com`, `boris@example.com` и `vera@example.com` пароль `deshielo-demo`.
4. В Xcode откройте **Product → Scheme → Edit Scheme → Run → Arguments** и в **Arguments Passed On Launch** добавьте:
   ```
   -CommunityURL http://127.0.0.1:8090
   ```
5. Запустите приложение на симуляторе. Появится вкладка «Сообщество»: можно зарегистрироваться, опубликовать рецепт с фото и оценить чужой.

На настоящем iPhone `127.0.0.1` — это сам телефон, поэтому для него сервер нужен в интернете (см. ниже) или хотя бы в локальной сети: запустите `./pocketbase serve --http 0.0.0.0:8090 …` и укажите `-CommunityURL http://<IP вашего Mac>:8090`.

> Без сервера вкладку можно посмотреть на демо-данных: в отладочной сборке аргумент `-DemoData` включает сообщество «в памяти», без сети.

## Сервер в интернете

### Где разместить

Пользователи вводят почту и имя — это персональные данные. По закону 152-ФЗ данные граждан России нужно записывать и хранить в базах на территории России. Поэтому берите **VPS у российского провайдера** — облака Timeweb, Selectel, Yandex Cloud, VK Cloud, REG.RU и другие. Их можно оплатить российской картой.

Для начала хватит самого маленького тарифа: 1 ядро, 1 ГБ памяти, 10–20 ГБ диска под фото, Ubuntu 22.04 или 24.04. Ещё понадобится домен, например `community.ваш-домен.ru`: в DNS добавьте A-запись с IP сервера.

### Установка

На сервере (по SSH):

```bash
sudo useradd --system --create-home --home-dir /opt/deshielo deshielo
cd /opt/deshielo
sudo -u deshielo curl -fsSLO https://github.com/pocketbase/pocketbase/releases/download/v0.40.5/pocketbase_0.40.5_linux_amd64.zip
sudo -u deshielo unzip pocketbase_0.40.5_linux_amd64.zip pocketbase
```

Скопируйте с компьютера папки сервера:

```bash
scp -r server/pb_migrations server/pb_hooks root@<IP сервера>:/opt/deshielo/
ssh root@<IP сервера> chown -R deshielo /opt/deshielo
```

Создайте службу `/etc/systemd/system/deshielo.service`:

```ini
[Unit]
Description=Deshielo community (PocketBase)
After=network.target

[Service]
User=deshielo
WorkingDirectory=/opt/deshielo
ExecStart=/opt/deshielo/pocketbase serve community.ваш-домен.ru --dir /opt/deshielo/pb_data --migrationsDir /opt/deshielo/pb_migrations --hooksDir /opt/deshielo/pb_hooks
AmbientCapabilities=CAP_NET_BIND_SERVICE
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Запустите её и создайте администратора:

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now deshielo
sudo -u deshielo /opt/deshielo/pocketbase superuser upsert you@ваш-домен.ru 'длинный пароль' --dir /opt/deshielo/pb_data
```

Когда в команде `serve` указан домен, PocketBase сам слушает порты 80 и 443 и получает сертификат Let's Encrypt. Откройте эти порты в файрволе провайдера. Проверка: `https://community.ваш-домен.ru/api/health` должен ответить `API is healthy`.

### Настройки в панели администратора

Панель: `https://community.ваш-домен.ru/_/` → **Settings**:
- **Application**: укажите адрес `https://community.ваш-домен.ru`. Он нужен для ссылок в письмах.
- **Mail settings**: SMTP для писем «Забыли пароль?». Подойдёт почта для домена у любого провайдера. Без SMTP восстановление пароля работать не будет.
- **Backups**: включите автоматические копии (например, ежедневно) и отправку в S3-совместимое хранилище — у российских облаков оно есть. Можно и просто копировать папку `pb_data`.

### Подключите приложение

В `Config/Shared.xcconfig`:

```
COMMUNITY_SERVER = community.ваш-домен.ru
COMMUNITY_SUPPORT_EMAIL = support@ваш-домен.ru
```

Адрес пишется без `https://`, приложение добавит его само. Почту покажут в правилах сообщества — App Store требует контакт для жалоб. Пересоберите приложение — вкладка «Сообщество» появится.

### Обновления

- **Схема и логика**: замените папки `pb_migrations` и `pb_hooks` на сервере и перезапустите службу (`sudo systemctl restart deshielo`). Новые миграции применятся сами.
- **PocketBase**: замените файл `pocketbase` той же версии, что проверена в CI (`POCKETBASE_VERSION` в `.github/workflows/ios.yml`). Перед обновлением сделайте резервную копию.

## Модерация

Магазин приложений требует, чтобы на жалобы реагировали быстро. Заглядывайте в панель хотя бы раз в день.

- **Жалобы**: коллекция `reports`. В записи видно, кто пожаловался, на что и почему.
- **Скрыть рецепт или отзыв**: откройте запись в `recipes` или `reviews` и включите поле `hidden`. Автор увидит в приложении пометку «Скрыт модератором». Рейтинг пересчитается без скрытого отзыва.
- **Удалить** запись можно там же. Вместе с рецептом удаляются его фото и отзывы.
- **Заблокировать нарушителя**: удалите его запись в `users` — уйдут и все его материалы.
- **Порог автоскрытия** (3 жалобы) — константа `HIDE_AFTER_REPORTS` в `server/pb_hooks/lib/community.js`.
- **Фильтр слов** — списки `RUSSIAN_PATTERNS` и `LATIN_PATTERNS` в том же файле. Изменения файлов в `pb_hooks` PocketBase подхватывает сам и перезапускается.
- **Подтверждение почты**: если появится спам, разрешите публикации только подтвердившим почту — добавьте `&& @request.auth.verified = true` в правила создания `recipes` и `reviews` (панель → коллекция → **API Rules**). Понадобится SMTP.

## Требования App Store

Для приложений, где пользователи публикуют контент (Guideline 1.2), в Deshielo уже есть:
- согласие с **правилами сообщества** при регистрации — они открываются из формы и из аккаунта;
- **фильтр** грубых слов на сервере;
- кнопка **«Пожаловаться»** у каждого рецепта и отзыва и автоскрытие по жалобам;
- **«Скрыть автора»** — его рецепты и отзывы пропадают из ленты пользователя;
- **контакт** модератора (`COMMUNITY_SUPPORT_EMAIL`);
- **удаление аккаунта** прямо в приложении, со всеми материалами (Guideline 5.1.1(v)).

При публикации:
- **App Privacy** в App Store Connect: теперь данные собираются. Укажите **Contact Info → Email Address** и **Name** (имя в сообществе), **User Content → Photos** и **Other User Content** (рецепты, отзывы), **Identifiers → User ID**. Цель — App Functionality, данные связаны с пользователем, для трекинга не используются. Без сервера сообщества (пустой `COMMUNITY_SERVER`) по-прежнему подходит «Data Not Collected».
- **Политика конфиденциальности** должна описывать, какие данные хранятся (почта, имя, рецепты, отзывы, фото), где (сервер в России), зачем и как их удалить (кнопка «Удалить аккаунт»).
- **Возрастной рейтинг**: в анкете отметьте, что есть пользовательский контент.
- **Закон о персональных данных**: кроме хранения в России, 152-ФЗ требует от оператора данных, в частности, уведомить Роскомнадзор и опубликовать политику обработки. Требования меняются, поэтому перед запуском уточните их у юриста.

## Тесты

- `server/tests/run.sh путь/к/pocketbase` поднимает чистый сервер и проверяет больше 80 сценариев: права доступа, черновики, отзывы и рейтинги, поиск, фильтр слов, жалобы, удаление аккаунта.
- Тесты приложения `DeshieloTests/CommunityLiveTests.swift` проверяют настоящий клиент iOS на настоящем сервере: регистрацию, загрузку фото, поиск, отзывы и удаление аккаунта. Локально они пропускаются. Чтобы их включить, задайте переменную `COMMUNITY_TEST_URL` в схеме тестов.
- В CI обе проверки идут при каждом пуше: на Linux — тесты API, на macOS — тесты приложения против запущенного рядом PocketBase.

Сервер общий: Android-приложение будет работать с тем же REST API PocketBase (у PocketBase есть официальный SDK для Dart/Flutter, для Kotlin достаточно обычного HTTP-клиента). Формат данных — в `server/pb_migrations`.
