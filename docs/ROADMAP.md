# Планы развития

## Версия для Android

Рецепты уже отделены от кода: папку `Shared/Content/` с JSON можно напрямую использовать в Android-приложении. Рекомендуемый стек:

- **Kotlin + Jetpack Compose** — нативный интерфейс, близкий по устройству к SwiftUI. Экраны переносятся почти один в один.
- **Glance** — виджеты для Android: «Рецепт дня» и интерактивный список покупок.
- **DataStore** или **Room** — избранное, дневник, список покупок.
- Таймеры — уведомление переднего плана (foreground service) вместо Live Activity.
- Публикация — **RuStore** (основной канал в России) и Google Play.

Чтобы не дублировать логику (пересчёт порций, склонения, слияние покупок), её можно позже вынести в общий модуль на **Kotlin Multiplatform** и подключить к обеим версиям.

Контент удобно хранить в отдельном репозитории или подмодуле, чтобы обе версии брали одни и те же JSON-файлы.

Сервер сообщества общий: Android-версия работает с тем же REST API PocketBase из `server/` (см. [COMMUNITY.md](COMMUNITY.md)).

## Новые рецепты без обновления приложения

Сейчас рецепты вшиты в приложение — новые появятся только с обновлением в App Store. Следующий шаг:

1. Выложить JSON из `Shared/Content/` на любой хостинг: GitHub Pages, Yandex Object Storage, Firebase Hosting.
2. При запуске приложение скачивает свежий каталог (с проверкой ETag), проверяет его и сохраняет. Если сети нет или файл повреждён, используется встроенный каталог. Загрузчик в `Shared/Data/Catalog.swift` уже устойчив к отсутствующим полям.
3. Для редакции без программиста — headless CMS (Strapi, Directus), которая выгружает тот же JSON.

## Фото и видео

- Собственная фотосъёмка блюд и пошаговые фото — самое заметное улучшение для «наглядности».
- Короткие вертикальные видео к сложным техникам (сферификация, оттяжка, кнель).
- Хранить медиа на CDN и подгружать по мере необходимости, а в приложении оставить генеративные обложки как заглушки.

## Синхронизация между устройствами

- **iCloud (CloudKit)** — избранное, дневник и меню на всех устройствах пользователя, без собственного сервера и регистрации. Нужен платный аккаунт разработчика.
- Общий список покупок для семьи — через CloudKit Sharing.

## Монетизация

- **Freemium**: часть коллекций («Высокая кухня», новые «Шефы») — по подписке через StoreKit 2.
- **Партнёрские ссылки**: у маркетплейсов (например, Ozon) и CPA-сетей есть партнёрские программы. Ссылки из «Заказать продукты» могут приносить комиссию. Переговоры о прямой интеграции с сервисами доставки — следующий уровень: с API можно собирать корзину целиком.
- **Спецпроекты**: коллекции в партнёрстве с ресторанами и шефами.

## Сообщество

Сейчас есть публикация рецептов с фото, поиск, оценки и отзывы с фото, жалобы и модерация (см. [COMMUNITY.md](COMMUNITY.md)). Дальше:
- подписки на авторов и лента «от тех, на кого вы подписаны»;
- подборки сообщества — например, «рецепт недели», который выбирает редакция;
- пошаговые фото в рецептах сообщества;
- вход через Apple ID и подтверждение почты;
- уведомления об ответах и новых отзывах на ваши рецепты.

## Функции

- Поделиться рецептом картинкой: красивая карточка через `ImageRenderer` для Telegram и сторис.
- Рекомендации на основе дневника и сезона, push-уведомления «сегодня в сезоне».
- Голосовое управление в режиме готовки («дальше», «назад»).
- Apple Watch: таймеры и шаги на запястье.
- Версия для iPad (сейчас приложение только для iPhone).
- Английская локализация и публикация в других странах.

## Перед коммерческим запуском

- Проверить ссылки сервисов доставки на реальных устройствах (`delivery.json`).
- Юридически проверить использование имён шефов, названий сервисов и цитат.
- Подготовить политику конфиденциальности. Без сообщества приложение не собирает данные, но страница всё равно нужна для App Store. С сообществом в ней нужно описать почту, имя, рецепты, отзывы и фото пользователей (см. [COMMUNITY.md](COMMUNITY.md)).
